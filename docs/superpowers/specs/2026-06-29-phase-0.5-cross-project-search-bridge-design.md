# SyberMem Phase 0.5 — 跨项目搜索过渡桥设计

> 在 Core CLI 完成之前，用最小改动让跨项目搜索立刻可用：project.yaml 身份 + 用户级注册表 + Grep 跨项目搜索。

**Date:** 2026-06-29
**Status:** Draft
**Scope:** Phase 0.5 过渡桥。只做 project identity、项目注册表、workspace search。不做 SQLite/Core CLI/Portfolio/Promote/Team/Obsidian。
**Parent spec:** `docs/superpowers/specs/2026-06-29-sybermem-cross-project-and-team-memory-spec.md`

---

## 1. Background & Problem

SyberMem 的跨项目与团队记忆扩展方案（requirement-003）定义了 Phase 0 到 Phase 6 的实施路径。Phase 0（架构决策确认）已完成。

Phase 1（Core CLI 基础）需要开发一个独立的 Python CLI，这需要时间。但跨项目搜索的核心价值可以**不等 Core 就先验证**——只要项目有身份、用户有注册表、search 能跨项目 Grep。

Phase 0.5 是 Phase 0 和 Phase 1 之间的过渡桥。

---

## 2. Design Goal

让用户**立刻能在项目 A 的会话中搜到项目 B 的记录**，验证 Hub 的核心价值。

### 三个交付物

1. **`project.yaml`** — 每个项目的稳定身份
2. **`~/.sybermem/projects.yaml`** — 用户级项目注册表
3. **`/sybermem-search --scope workspace`** — 跨已注册项目搜索

---

## 3. project.yaml（项目身份）

### 位置

```text
<project>/.sybermem/project.yaml
```

### Schema

```yaml
schema_version: 1
project_id: prj_<ULID>
slug: <从 git remote 或目录名推导>
name: <从 git remote 或目录名推导>
repository:
  remote: <git remote get-url origin，如果有>
  default_branch: <git symbolic-ref HEAD，如果有>
created_at: <ISO8601>
```

### 生成规则

- 由 `/sybermem-init-project` 在 Step 7（创建/刷新 managed files）时自动生成
- `project_id` 使用 ULID（或 UUID4），首次生成后永不变
- `slug` 从 git remote URL 的最后一段推导（例如 `github.com/user/eszyzu` → `eszyzu`）；无 remote 时用当前目录名
- `name` 默认等于 slug，用户可手动修改
- 已有 `project.yaml` 时跳过，不覆盖
- `repository.remote` 和 `repository.default_branch` 从 git 获取，获取失败时留空

### Health check 检测

`check_project_health.py` 新增检查：
- `.sybermem/project.yaml` 是否存在
- 不存在时报告 `missing`，`actions_needed` 加 `"create .sybermem/project.yaml"`

## 4. `~/.sybermem/projects.yaml`（用户级注册表）

### 位置

```text
~/.sybermem/projects.yaml
```

Windows 示例：

```text
C:\Users\<username>\.sybermem\projects.yaml
```

### Schema

```yaml
schema_version: 1
projects:
  - project_id: prj_01JXYZ...
    slug: eszyzu
    path: D:/workspace/eszyzu
    remote: github.com/example/eszyzu
    registered_at: 2026-06-30T10:00:00+08:00
  - project_id: prj_01JABC...
    slug: sybermem
    path: D:/adr-project
    remote: github.com/goudaren0528/sybermem
    registered_at: 2026-06-30T10:00:00+08:00
```

### 注册时机

`/sybermem-init-project` 生成 `project.yaml` 后，自动把当前项目追加到 `~/.sybermem/projects.yaml`：

1. 读 `~/.sybermem/projects.yaml`（不存在则创建空文件）
2. 按 `project_id` 查找：
   - 已存在 → 更新 `path`（支持项目目录移动后重新定位）
   - 不存在 → 追加新条目
3. 写回文件

`~/.sybermem/` 目录不存在时自动创建。

### 注册表不做的事

- 不做 SQLite 索引（Phase 2）
- 不做项目状态缓存
- 不做自动发现未注册项目
- 不做团队同步

## 5. `/sybermem-search --scope workspace`

### 扩展现有 search skill

当前 `/sybermem-search` 默认在当前项目搜索。新增 `--scope` 参数：

```text
/sybermem-search barcode                     # 默认: 当前项目
/sybermem-search barcode --scope project     # 显式: 当前项目
/sybermem-search barcode --scope workspace   # 新增: 跨所有已注册项目
```

### workspace 搜索流程

1. 读 `~/.sybermem/projects.yaml` 获取已注册项目列表
2. 对每个项目：
   - 检查 `path` 是否存在且有 `.sybermem/INDEX.md`
   - 不可达的项目标注 `[unavailable]` 并跳过
3. 对每个可达项目，按现有检索路径搜索：
   - topic → 读该项目的 Topic Index
   - keyword → Grep 该项目的 Key Conclusions + Archived Conclusions + records 正文
   - record ID → 在该项目内定位
4. 结果附带 `[project: <slug>]` 来源标注
5. 按项目分组展示

### 输出格式

```markdown
## SyberMem Workspace Search: "barcode"

### [eszyzu] (3 results)
1. **[decision-012]** #barcode — 移动端扫码降级策略 (2026-06-20)
   - File: D:/workspace/eszyzu/.sybermem/decisions/...

2. **[change-045]** #barcode — 添加 ZXing fallback (2026-06-22)
   - File: D:/workspace/eszyzu/.sybermem/changes/...

### [sybermem] (0 results)
No matches.

### [old-project] [unavailable]
Project path not accessible: D:/workspace/old-project
```

### Phase 0.5 限制

- 只用 Grep，不用 SQLite FTS（Phase 2 升级）
- 不做跨项目 ranking（按项目分组，项目内按现有排序）
- 不做跨项目 relation/phase 解析
- 不做 `--scope team`（Phase 4）
- 项目不可达时跳过并标注，不报错中断

## 6. SessionStart context 增强

`session_start_context.py` 在注入项目 context 时，如果 `.sybermem/project.yaml` 存在，额外注入一行：

```text
Project: eszyzu (prj_01JXYZ...)
```

让 AI 在会话开始时就知道当前项目的身份和 slug。

## 8. Backward Compatibility

- 没有 `project.yaml` 的项目：所有现有行为不变。`/sybermem-search` 默认仍是 project scope。
- 没有 `~/.sybermem/projects.yaml` 的用户：`--scope workspace` 提示"没有已注册项目，请先在目标项目里运行 /sybermem-update"。
- `project.yaml` 在 init-project 时自动生成，不需要用户手动创建。

---

## 9. Out of Scope

Phase 0.5 明确不做：
- SQLite FTS 索引（Phase 2）
- Core CLI（Phase 1）
- Portfolio 项目组合视图（Phase 2 后）
- Promote / Personal Lesson（Phase 3）
- Team Git / Publish / Review（Phase 4）
- Obsidian（Phase 2 后）
- User Identity（Phase 1）
- Global URI（Phase 1）
- `--scope team` 搜索（Phase 4）

---

## 10. Success Criteria

1. `/sybermem-init-project` 自动生成 `.sybermem/project.yaml`（含 project_id 和 slug）
2. `/sybermem-init-project` 自动把项目注册到 `~/.sybermem/projects.yaml`
3. `/sybermem-search hooks --scope workspace` 能搜到多个已注册项目的结果
4. SessionStart context 包含 project slug
5. health check 能检测 `project.yaml` 缺失
6. 已有项目不受影响，默认搜索行为不变
