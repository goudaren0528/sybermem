# update-overview Skill

更新项目全貌，保持 OVERVIEW.md 与项目实际状态同步。

## 触发条件
| 条件 | 说明 |
|------|------|
| 新模块未提及 | 新增模块目录，OVERVIEW未记录 |
| 架构调整 | 技术栈或架构变化 |
| 新增重要功能 | 核心功能变化 |
| 更新时间过期 | 超过阈值（1个月） |
| 用户手动触发 | 用户主动请求 |

## 流程

### Step 1: 扫描当前项目状态
- 目录结构变化
- 新增配置文件
- 新增模块

### Step 2: 对比现有 OVERVIEW.md
- 技术架构部分是否准确
- 核心功能部分是否完整
- 目录结构说明是否更新

### Step 3: 识别需要更新的内容
- 新增模块 → 技术架构部分
- 新增功能 → 核心功能部分
- 架构变化 → 技术栈列表

### Step 4: 增量追加新内容
**原则：不删除已有内容，只追加新内容**

### Step 5: 更新"最后更新时间"
- 最后更新时间：YYYY-MM-DD
- 更新内容摘要

### Step 6: 更新关键决策索引

### Step 7: 更新特殊处理提醒

## 自动检测实现
AI 在以下情况主动判断是否需要更新：
- 创建新模块目录时
- 新增重要 ADR 时
- 技术栈变化时
